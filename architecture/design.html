Design system and motion

The design direction is minimal and sharp edged: zero radius everywhere, nothing shadowing at rest, one sage accent on a clay-white page, and a drawn vessel wherever a photograph is missing. That drawing is not decoration bolted on - it is a small geometry engine shared by the hero jar and every placeholder, with a seeded pseudo-random generator so the server and the browser produce byte-identical paths. Motion is gated behind one reduced-motion media query and carried by two primitives, a one-shot reveal and a capped stagger.

The .dark block defines a complete dark palette, but nothing in the app ever adds the dark class: there is no theme provider, no next-themes, and the root layout's html element carries only the font variables. Dark mode in the product is dormant CSS. These architecture pages have their own independent dark mode.

Custom utilities carry the house rules: tnum for tabular numerals so price columns do not jitter, ghost-hover which tints an icon button by 3.5 percent rather than filling it, link-underline which draws a hairline from the left via a background size transition, pb-safe for the mobile inset, and the dialog enter and exit utilities.

Motion, and the single gate

Every animation lives inside one @media (prefers-reduced-motion: no-preference) block, so reduced motion is handled in CSS rather than in JavaScript. The house easing is cubic-bezier(0.22, 1, 0.36, 1) throughout. Dialogs rise 6 px and fade with no zoom, because scaling a sharp-edged sheet reads as an app. Kiln-label state styles sit outside the gate, because they are colour changes rather than motion.

Reveal takes delay, isGroup and isScrollLinked. Its effect bails when there is no node, when IntersectionObserver is undefined (server rendering and jsdom), or when the block is scroll linked and the browser supports animation-timeline: view() - in that case CSS drives the fade off scroll position and the observer never starts. The observer uses a 0.15 threshold and disconnects on first intersection, so a reveal never replays. Two invariants: content renders visible, so a reader with JavaScript off or reduced motion on never sees a blank block, and a group reveal moves nothing itself - it only flips data-revealed so its .reveal-item children may start, one observer per grid rather than one per card.

stagger.ts:toRevealDelay(index) returns a --reveal-delay custom property with a 40 ms step capped at 8, so the fourth row of a grid never waits on the first three. The value was retimed down from the 130 ms found in the reference set, recorded in docs/design/animation-study.md.

The drawing engine

frontend/src/lib/drawing/vessel.ts is shared by the hero jar and every placeholder, so every drawn piece on the site is shaded the same way.

  • Seeded randomness. seededRandom(seed) is a mulberry32-style generator returning values in [-0.5, 0.5). The reason is stated in the source: it keeps the hand wobble identical on the server and the client, so hydration matches. Default seeds are 515 for hatching and 9981 for the glaze wash.
  • catmullRom builds segments with reflected phantom endpoints; wallSpline(points, seed, wobble) jitters only the control points, never the on-curve endpoints; closedBody runs down the near wall, across the foot and back up the far wall.
  • parsePath(d) reads an authored outline back into a spline, and halfWidthReader(wall, axisX) samples it so that half widths are read off the wall that is actually drawn and shading can never drift off the silhouette.
  • RING_SQUASH = 0.17 foreshortens a horizontal circle seen slightly from above; ringArc approximates an elliptical arc with a single cubic.
  • hatchArcs draws cross-contour hatching from the piece's own rings, offsetting rows like brickwork so it never reads as a grid, lighting from the upper left so the right edge is darkest and the left third is bare, and tagging each stroke with a band index so a reveal can run from the lit side into the shadow.
  • washBand gives the glaze a level top and an unevenly crawled bottom.

jar.ts holds the hand-authored moon jar outline in a 400 by 400 space, including the mouth crescent that gives the rim depth. jar-surface.ts derives everything else from it at module load: the body path, the half width reader, the hatch strokes, four throwing rings each split into a darker and a fainter arc, the glaze band and drip, the label anchors and the thumb dent that stopped the jar from being symmetrical.

HeroIllustration computes HATCH and RINGS once at module scope and choreographs the paint: ground and shadow, clay fill, optional grain filter, gradients, throwing rings, four hatch bands staggered 150 ms apart, the glaze wipe, foot and dent, the mouth, and the outline last in source but with zero delay. Every drawn path carries pathLength={1} so one dash spans any path regardless of its real length. The chosen finish is baked into every gradient, clip and filter id so several variants can coexist on one page. It is labelled with a title and desc pair describing the lighting, the drip, the dent and the four labels.

KilnLabels is the one signature device: hairline leader lines staggered 120 ms apart whose dash pattern is removed once drawn so the line stays continuous, a small dot, and an optional transparent hit circle with a role, a tab index and an accessible label. The wrapper is hidden from assistive technology when non-interactive and, when interactive, the duplicate text spans are hidden instead, so nothing is announced twice.

Placeholders and carousels

components/media/vessels.ts describes the seven pieces drawn where a photo is missing, each a profile, a glaze, ring positions, an optional handle and a seed, run through the same engine. PlaceholderImage is a server component that reuses the hero's gradient stack and keeps strokes hairline at any size with a non-scaling stroke. useImageCarousel wraps Embla and holds the reduced-motion preference in a ref fed by a matchMedia listener, so a preference change never forces a re-render mid-drag; the preference is passed as Embla's jump argument to skip the easing.

Storybook and verification

  • src/lib/storybook/viewports.ts defines mobile 375x667, tablet 768x1024, laptop 1366x768 and desktop 1440x900, and atViewport(key) returns the globals object a story spreads. The repo rule is that every presentational component gets stories at all four.
  • .storybook/preview.tsx wraps every story in the same font variables the app uses, imports globals.css, and sets a11y: { test: "error" }, so accessibility violations fail the Vitest storybook project, which runs in a real headless Chromium.
  • frontend/scripts/measure-responsive.mjs is a Playwright script that serves the static Storybook and prints computed sizes for buttons, inputs, cards, badges and tables across three viewports. It measures and does not assert.
  • frontend/scripts/lighthouse.ts runs the desktop and then the mobile Lighthouse CI config, with warn-level assertions at a minimum score of 0.85 for performance, accessibility and best practices.
  • docs/design/animation-study.md is where the house values came from: ten reference pages read out of live stylesheets, catalogued as techniques, which is the source of the 12 px travel, the 40 ms capped stagger, the 3.5 percent ghost hover, the pathLength=1 draw and the fixed-height callout rule.

There is no video or motion-capture verification tooling in the repo; motion is checked through Storybook, the measurement script and Lighthouse.

  2. frontend/src/app/globals.css[data-revealed] .reveal-item starts the children's fade, inside the reduced-motion gate.

Edge cases and failure handling

  • Determinism is load bearing. The seeded generator, the module-scope hatch and ring computation and the "stays identical between renders" test are what keep server and client geometry in agreement.
  • Reveal starts visible, and inverting that would blank the page for readers with JavaScript off or reduced motion on.
  • Scroll-linked reveal is opt-in and should not be used on a pinned panel, whose view progress would hold still along with it.
  • Reduced motion is a CSS concern, so no component needs to branch on it - except the carousel, which holds it in a ref precisely to avoid re-rendering mid-drag.
  • --radius: 0px is global, so any rounded corner in a component is a deliberate opt-out.
  • Dark mode tokens exist but are unreachable in the product.
  • Filter and gradient ids are namespaced by finish or vessel kind, so two illustrations on one page cannot collide.

Tests

  • frontend/src/components/motion/stagger.test.ts covers the 40 ms step, the cap at 8 and negative clamping.
  • frontend/src/features/home/components/jar-surface.test.ts covers seven cases: the silhouette closing, half widths being read off the drawn wall, rings running from shaded to front, hatching the shaded side while leaving the lit side bare, revealing from the lit side toward the shadow, the glaze band closing, and - the determinism guard - staying identical between renders so server and client agree.
  • vessel.ts has no direct test; it is covered transitively through jar-surface.test.ts.
  • Stories: Reveal.stories.tsx (default, delayed, scroll linked and group, at four viewports), KilnLabels.stories.tsx, PlaceholderImage.stories.tsx, HeroIllustration.stories.tsx (three finishes plus static), and the home section stories.
