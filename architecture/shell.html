Storefront shell and navigation

Every storefront page renders inside one server layout that fetches the site settings once, mounts the cart and wishlist providers above the router, and hands the rest of the tree a focusable main. The header is the only stateful part of that shell: it reads a badge-sized cart query rather than the whole cart, announces a changed count through a polite live region, collapses to a single back link on cart and checkout, and opens the search panel and the mobile sheet from the same container. Underneath, the RSC Apollo client only calls Clerk when the proxy actually stamped the request, and a Clerk account change resets the whole store rather than evicting fields by hand.

Architecture

How it works

The two layouts

frontend/src/app/layout.tsx is the only place globals.css is imported. It wraps the tree in ClerkProvider (with clerkAppearance and clerkLocalization from components/providers/clerk-appearance.tsx), then ApolloProvider, and renders the Toaster as a sibling after children but still inside the Apollo provider, so a toast raised on one route survives the navigation to the next. WebVitalsReporter sits outside Apollo entirely. Static metadata gives the title template %s · Poetry & Pottery; viewport sets themeColor: "#f7f4ef" and viewportFit: "cover" for the safe-area padding the mobile nav relies on.

app/(storefront)/layout.tsx is a server component. It awaits getSiteSettings() once, derives whatsappUrl through buildWhatsAppUrl(number, "Hi, I have a question about Poetry & Pottery."), and then mounts, in order: CartProvider, WishlistProvider, the skip link, the announcement bar when announcement_text is set, SiteHeaderContainer, main, SiteFooter, MobileNavContainer and SignInPromptContainer. Both providers are above the router, which is why the badge number does not refetch on every navigation.

PageShell

components/layout/PageShell.tsx is the width primitive rather than a chrome wrapper: it never renders the header or the footer. Props are children, className, column ("full", "wide" or "narrow", default full) and isBusy. SHELL is mx-auto w-full max-w-7xl px-4 md:px-8 and COLUMN maps wide to max-w-5xl and narrow to max-w-3xl; column="full" renders a single bare div so a page can run its own full-bleed sections. aria-busy is emitted as "true" or omitted, never as the string "false".

Every loading.tsx, the storefront error.tsx and not-found.tsx use it, as do SiteHeader and SiteFooter for their own inner bar, and roughly two dozen feature containers.

Two routes bypass it and hand-inline the same classes: app/(storefront)/archive/page.tsx writes out the max-w-7xl wrapper itself, and app/(storefront)/notify/unsubscribe/page.tsx writes out a max-w-3xl one, which is what column="narrow" would have given it. newsletter/unsubscribe, its twin, does use PageShell. Those two are fixed on feat/design-refresh, which is not in this branch's ancestry; see the branch page.

Focus and the skip link

SkipLink takes one prop, targetId, and renders an sr-only anchor that becomes focus:not-sr-only focus:absolute focus:top-2 focus:left-2 focus:z-50 on focus. Its target is <main id="main" tabIndex={-1} className="... focus:outline-none">: the negative tab index is what lets the hash move focus at all, and the suppressed outline is deliberate, because the element is only ever focused programmatically.

There is no route-change focus rule. Nothing watches usePathname() to move focus or announce the new page. The two .focus() calls in frontend/src are the roving arrow keys in OptionGroupPicker and the opener restore in MobileMenuSheet. A keyboard visitor who follows a link lands wherever the browser leaves them and has the skip link as the recovery.

Loading, error and not-found

  • Nineteen loading.tsx files, all under (storefront), all built from PageShell plus the primitives in components/layout/PageSkeleton.tsx: SkeletonBlock (always aria-hidden, animate-skeleton bg-ash), SkeletonHeading, SkeletonGrid and SkeletonRows. Each one mirrors the real page's column and grid, so the swap does not reflow: products/loading.tsx and search/loading.tsx are identical filter-rail-plus-grid shapes, and the three detail skeletons under orders, registrations and workshops/bookings share one layout.
  • One error.tsx, at (storefront)/error.tsx. It logs through the frontend logger in an effect, and handleRetry wraps router.refresh() and then reset() in startTransition, because reset() on its own replays the same failed payload. It renders PageError, whose retry label flips to "Trying again" while the transition is pending. There is no admin error.tsx.
  • not-found.tsx is an async server component: it awaits getArchiveProducts(4) and offers four archive pieces as the way back, rather than a bare 404.

The toaster

One sonner Toaster in components/providers/toaster.tsx: position="bottom-right", offset={{ bottom: 24, right: 24 }}, mobileOffset={{ bottom: 80 }} to clear the 64 pixel mobile nav and its safe-area inset, duration={3500}. The live region is sonner's own; the application only names it, with containerAriaLabel="Studio notices", and labels the dismiss control with closeButtonAriaLabel="Dismiss this notice". A toast is the only rollback signal for every optimistic mutation in the app.

The header

SiteHeaderContainer takes contactPhone and whatsappUrl from the layout and owns isMenuOpen, isSearchOpen, countAnnouncement and a lastCounts ref. It reads useCartCount(), useWishlistIds(), useUser() and useClerk(), and passes flat props down to the presentational SiteHeader.

frontend/src/features/layout/types.ts:toFocusedHeader, the whole rule.
PathnameBack link
/checkout/cart, "Back to cart"

The focused variant drops the divider, the desktop <nav aria-label="Main">, the search button, the wishlist and cart icon links, the admin link, the mobile menu button and the account button. It keeps the sticky bar, the wordmark, the live region and one ArrowLeft link. The point is that a shopper in the middle of paying is not offered a way to wander off.

The count announcer. An effect compares the lastCounts ref against the current cart and wishlist numbers and sets countAnnouncement from whichever moved, through toCartAnnouncement or toWishlistAnnouncement; the cart wins when both changed in one render. The header renders it as <p aria-live="polite" aria-atomic="true" class="sr-only">. The badges themselves are aria-hidden and the number lives in the icon link's aria-label, so a screen reader hears the count once rather than twice. formatBadgeCount caps the visible number at 9+.

The search panel

  • The header button carries aria-expanded={isSearchOpen}; opening it closes the mobile menu first. SearchMenuContainer returns null when closed rather than hiding a mounted panel, so each open starts with a clean draft and re-reads the recent searches.
  • The typeahead is the Suggest operation in frontend/src/graphql/suggest.query.gql, selecting pieces, events and workshops in one round trip. The term is passed through useDeferredValue rather than a timer, gated at MIN_SUGGEST_LENGTH = 2, and previousData keeps the old rows on screen so the list never blinks empty between keystrokes.
  • The input is a role="combobox" inside a <form role="search">, with aria-controls, aria-autocomplete="list" and aria-activedescendant driven by toOptionId(panelId, activeIndex) over ids from useId(). Arrow keys move through nextActiveIndex, Escape closes from the input and from a document-level listener, and Enter follows the active option or falls back to toSearchHref.
  • Recent searches live in localStorage under poetry.recent-searches, capped at MAX_RECENT_SEARCHES = 5.
  • It is not a Radix dialog: dismissal is a full-screen aria-hidden button behind the panel, and there is no focus trap. The input is autoFocus.

The mobile menu sheet

MobileMenuContainer is wrapped in Suspense by the header, because it calls useSearchParams(): the shelf and the archive are the same path and differ only by ?view=, so isActiveLink(pathname, view, href) needs the query to mark the right row. MobileMenuSheet is built on the Radix Dialog behind components/ui/sheet.tsx, so the focus trap is Radix's. Focus restore is not, because the sheet is opened from the header button rather than a Radix Trigger: the container captures document.activeElement in onOpenAutoFocus and restores it in onCloseAutoFocus with event.preventDefault(), guarded on isConnected so a removed opener does not throw. Rows are min-h-11, a 44 pixel target.

MobileNav is the separate bottom bar: <nav aria-label="Primary">, fixed inset-x-0 bottom-0 with pb-safe lg:hidden, four destinations, and the same cart count.

CartCount and the two providers

frontend/src/graphql/cart.query.gql holds two operations. CartCount asks for the bare scalar cartCount; Cart pulls the whole basket through the CartFields fragment, including every line's selections, reference photos and product card. The provider is mounted in the layout, so without the split every route would fetch a full cart just to draw a badge. Both are refetched together by CART_REFETCH = { refetchQueries: ["Cart", "CartCount"], awaitRefetchQueries: true }.

  • CartProvider exposes { count, isSignedIn, isAdding, addToCart } and holds no optimistic state. Adding waits for the server, because stock is the server's call; success toasts with a "View cart" action. The count query is skipped entirely when signed out.
  • The optimistic cart lives one level down, in features/cart/hooks.ts:useCart(), which the cart page mounts: useOptimistic(cart, applyCartAction) plus useTransition over the quantity, remove and clear actions.
  • WishlistProvider exposes { ids, isSignedIn, isSaving, toggle, adoptIds } and does hold useOptimistic(ids, applyWishlistToggle). adoptIds is the lending hatch: the wishlist page already fetches the full list, so it lends those ids to the provider in an effect and returns them on unmount, and while they are lent the WishlistIds query is skipped rather than run twice.
  • Both context hooks throw a named error when used outside their provider.

resetStore on an account change

ResetStoreOnUserChange is an unexported component rendered first inside the Apollo provider. It bails while Clerk has not loaded, treats the first settle as "not a change" with an undefined sentinel in the ref, and otherwise calls client.resetStore() with a toast on failure. The trigger is the Clerk userId changing, so sign-in, sign-out and account switching are one code path. The source comment records the choice of resetStore over clearStore: it restarts the queries it cancels instead of leaving them empty, which matters because the header's own queries are live at that moment.

This is the only Apollo cache lifecycle call in the frontend, and the repo rule in CLAUDE.md names it exactly. docs/design/optimistic-audit.md is the stale one: it still says client.clearStore() in three places, and clearStore appears nowhere in frontend/src.

The RSC client and the proxy stamp

frontend/src/proxy.ts is Next 16's renamed middleware and is a bare clerkMiddleware(): it establishes the session and protects no route. Its matcher excludes static assets, so a render triggered for one of those paths arrives unstamped, and auth() throws when the stamp is missing.

lib/apollo/rsc-client.ts therefore checks before it asks:

  • const token = incoming.has("x-clerk-auth-status") ? await auth().then((s) => s.getToken()) : null;, where incoming is await headers().
  • The authorization header is set only when a token came back, so an unattributed render is served signed out rather than crashing. Every query this client makes is public, which is what makes that acceptable.
  • It also copies x-forwarded-for, falling back to x-real-ip, so the API's throttler does not bucket every server-side call under the Next server's own address.
  • Exports are getClient, query and PreloadQuery from registerApolloClient, one client per request.

The wordmark

features/layout/components/Wordmark.tsx is the whole brand surface on this branch: a next/link to / with aria-label="Poetry & Pottery home", setting the name in the heading face with the ampersand alone in the script face. It is text, not an image.

There is no drawn mark, no /brand route and no asset folder: frontend/public/ holds only a .gitkeep. There is also no NEXT_PUBLIC_SITE_URL; the frontend validates exactly three public variables (NEXT_PUBLIC_API_URL, NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY, NEXT_PUBLIC_LOG_LEVEL). What fills that role is lib/site-url.ts:toAbsoluteUrl(path), which rebuilds the origin per request from x-forwarded-host and x-forwarded-proto, defaulting to localhost:3030 over http; its only consumer is the prefilled WhatsApp message. There is no metadataBase, no sitemap.ts, no robots.ts and no icon or manifest route. All of that now exists on feat/design-refresh, which is not in this branch's ancestry: a drawn frontend/src/components/brand/Wordmark.tsx, eleven files under frontend/public/brand (the mark, the inline and stacked lockups with reverse variants, a favicon, two icons and an Open Graph image) and a validated NEXT_PUBLIC_SITE_URL read by the root layout. See the branch page.

Edge cases and failure handling

  • An unstamped render is served signed out. The proxy matcher excludes static-asset paths, and auth() throws without the stamp, so the RSC client checks the header first rather than catching.
  • The first Clerk settle is not an account change. Without the undefined sentinel the store would reset on every first paint, because Clerk reports no user before it loads.
  • reset() alone does not clear a failed route. The error boundary refreshes the router first, otherwise React replays the same failed payload.
  • Nothing moves focus on navigation. The skip link is the only keyboard recovery, and no route change is announced.
  • The search panel has no focus trap, so Tab can walk out of it into the page behind; Escape from anywhere closes it, which is the mitigation.
  • The mobile sheet's opener can be gone by the time it closes, which is why the restore is guarded on isConnected.
  • Signed-out visitors fire neither shell query. Both providers pass skip and fall back to zero and an empty array.
  • The wishlist page and the provider would otherwise fetch the same ids twice; adoptIds exists to stop that, and returns the provider to its own query on unmount.
  • Two routes bypass PageShell and repeat its classes by hand, so a change to the shell's padding would miss them.
  • The badge number can lag its page. CartCount and Cart are separate documents refetched together, but a mutation that fails between them leaves the badge to the next awaited refetch.
